# Investigation records

Read for deep or joint investigation records, decisions and continuity. Evidence.md owns the working note and observations. Joint agreement and replacement rules live in joint.md. These records are useful content, not mandatory phases, separate files or database tasks.

## Keep the meaning

Retain what the work needs to explain:

| Content | What matters |
|---|---|
| Issue | Claim, site, trigger, consequence, supporting evidence and current disposition |
| Proposed fix | Goal or issues answered, intended change, consequential tradeoffs and discriminating validation |
| Candidate | Recoverable implementation, exact baseline, dependency versions and applicable validation |
| Decision | User's answer and reason, affected work and unresolved choice |
| Coverage | Requested objects or scenarios covered, still open or explicitly unverified |

Link existing Contract and evidence rather than copying them into each proposal. Mark missing consequential information without inventing a value for every noun. Keep a supported issue when an implementation is rejected; a disagreement about shape need not reopen an unchanged fact. In report-only work, examine the proposed sites and evidence before calling a direction suitable.

Keep baseline and dependency versions with candidates and validation. Name combinations tested together. File overlap alone does not make candidates inseparable; actual dependencies do. When related issues produce a new impact or common cause, retain and verify that combined claim instead of duplicating an existing report.

When the user drops work or changes the goal, retain that decision and reconsider affected dependencies and conclusions. Preserve surviving work and its applicable evidence; an unrelated later message does not reopen dropped work.

## Continuity

Record the exact candidate, baseline, dependencies and evidence each assessment actually checked, with its conclusion and unresolved conditions. Name the versions assessed, not newer versions fetched while saving; inspect intervening changes before applying an assessment to them. A changed claim, candidate, dependency, ruling or observation requires reconsidering the affected conclusions, not automatically repeating all work.

Keep validation tied to its actual inputs. When those inputs change, distinguish checks rerun from evidence retained and explain why the retained evidence still supports the claim. An explanation or review-status change alone does not invalidate unchanged runtime evidence. Reassess a condition's resolution against the current claim, ruling and evidence; when an independent assessment is being relied on, its reader must check that resolution. This need not require a candidate edit or new execution. Joint publication and peer assent follow joint.md.

Preserve recoverable versions rather than overwriting evidence behind earlier conclusions. A saved patch names its base; a remote shelve names its exact revision, not a moving branch. Resume from the retained investigation, checking changed code, environment and assumptions. Keep the current goal and authority, candidate inputs, evidence, unfinished work, decisions and next action available. A previous report points to evidence; neither a new session nor the same record identity settles its applicability. Resume joint coordination through ledger.md.

## User decisions

Apply SKILL.md's authority rules before asking. Missing design detail or a broader recoverable fix does not itself require permission. For a real choice, explain the goal or ruling at stake, concrete consequences, useful options and recommendation, material uncertainty, and the action that needs the answer. A short question can cover these without a new template.

Retain the actual answer and identify affected work; a recommendation or peer agreement is not user acceptance. A question blocks only its named action. Continue independent useful work, preserving the candidate and unanswered choice. Solo deep work records this in its note, with no helper command. In joint work, use ledger.md's user wait and resolution so the shared state reflects the answer.

Keep durable decisions where later work can use them: a regression test or invariant at the owning boundary, a ruling with its rationale in the feature document, a retained measurement, or an open item for unavailable evidence. Do not add comments, asserts or tests merely to manufacture an exit for a disproved finding.
